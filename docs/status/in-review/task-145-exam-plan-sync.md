decision: D-pending (Task 145) A signed-in exam date is saved by updating `exam_date` for the course, then inserting when no row matched (and updating again if another tab inserted first), never by an upsert. Reason: the migration grants `update (exam_date)` only, and PostgREST's upsert sets every sent column (`on conflict … do update set course = excluded.course, …`), so an upsert would be refused for lacking update rights on `course`. The account's date wins on load; with no course on the device, the account's plan is used only when there is exactly one. Clearing the date deletes that course's plan; changing the course leaves the old course's plan in the account.
