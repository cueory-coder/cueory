decision: D-pending (Task 60) Delete-my-account is one database function, `public.delete_my_account()`, with no arguments: it deletes the caller's own `auth.users` row as its owner (security definer, empty search_path, signed-in students only) and relies on `on delete cascade` from every table that references auth.users, which its pgTAP test enforces for every current and future table in public. It does not end an access token already issued, so the account page signs the student out right after. Reason: Supabase's User Management docs say to reference auth.users with `on delete cascade` and that deleting the auth.users row ends the account's sessions; one function means no server key and no extra service, so the cost stays $0.
