# Technical decisions

One line each, newest at the bottom. Reasons are kept short on purpose.

- **D-01** Node 24 LTS, pinned in `.node-version`. It has long-term support and both CI and Cloudflare read this file.
- **D-02** TypeScript 6, not 7. Astro's type checker (`@astrojs/check`) supports only up to 6.
- **D-03** Tailwind v4 with `@theme` in `src/styles/tokens.css`. The default palette is removed so only tokens can
  be used.
- **D-04** Self-hosted fonts: Newsreader (headings) and Atkinson Hyperlegible Next (body). They're open source, built
  for legibility, and load no third-party font server.
- **D-05** Cloudflare **Pages**, not Workers. Cloudflare's docs tell new projects to start on Workers, but Workers
  builds can only be switched on or off for *all* non-production branches. Pages documents exactly what the brief asks
  for: "Preview branch control → Custom branches = `staging`" (feature branches never use the 500 free builds) and a
  one-click "Enable access policy" lock for previews. The site is plain static files, so moving to Workers later is a
  small change.
- **D-06** Hash-based CSP generated by Astro (`security.csp`). Header-only parts (`frame-ancestors`) are in
  `public/_headers`. CSS is never inlined, so styles stay hash-free.
- **D-07** GitHub repository visibility: **open question for Christian.** The repository is private. On a private
  personal repository, CodeQL and GitHub secret scanning need paid GitHub plans, and branch protection may too. Recommendation:
  make the code repository public (the code holds no secrets and no answer keys), and keep answer keys and reviewer
  files only in Supabase or a separate private repository (Task 2).
- **D-08** Extra secret scan with gitleaks in CI (free, open source), so secrets are caught even while the repository
  is private.
- **D-09** CodeQL workflow skips itself on a private repository instead of failing; it runs as soon as the repository
  is public.
- **D-10** Pages are built as `page.html` files (`build.format: 'file'`), so URLs have no trailing slash.
- **D-11** Unit tests with Vitest. Browser tests with Playwright plus axe accessibility checks at phone and desktop
  sizes.
- **D-12** Newsletter: **Kit** free plan (up to 10,000 subscribers, unlimited sends, unsubscribes handled, double
  opt-in). Alternatives checked: EmailOctopus, Sender and beehiiv cap free plans at 2,500; MailerLite cut its free plan
  to 250 in 2026; Buttondown's free plan is too small. Brevo has unlimited contacts but only about 300 sends a day.
- **D-13** The signup form is plain HTML that posts straight to Kit: no Kit script, no cookies on our pages, and it
  works without JavaScript. The CSP allows posting only to the exact Kit address set in `src/config/site.ts`.
- **D-14** Branch flow: feature branch → pull request into `staging` → locked staging site → pull request into `main`.
  The repository starts with one empty commit on `main` and `staging`, so even Task 1 arrives through a pull request.
- **D-15** The staging site lives at `staging.cueory.pages.dev` (Cloudflare's branch address), which the one-click
  preview lock covers. No `staging.cueory.app` address, so there's no second lock to manage.
- **D-16** Supabase keep-alive and backup jobs moved to Task 2, together with the Supabase projects they serve.
- **D-17** Dependabot security alerts on; Dependabot automatic security-fix pull requests off, because GitHub opens
  them against the default branch (`main`) and they would skip staging. Weekly version updates target `staging`.
